# GPU device recovery

Application automatically pauses on loss, quiesces pending asset/stream work, obtains a new adapter/device, rebuilds shared GPU ownership and commits only after validation. ECS identities, controller state, camera, CPU material definitions and scene hierarchy survive. Running loops resume with reset delta/accumulator; paused loops stay paused. Explicit concurrent `recoverDevice()` calls deduplicate. Failed rebuild preserves CPU recovery ownership and reports a retryable status. Disposal waits for recovery and prevents late publication. The [WebGPU specification](https://gpuweb.github.io/gpuweb/) requires resources from a lost device to be recreated; they cannot be transferred to the replacement device.

Mesh uploads retain canonical packed CPU vertices/indices. Textures retain source RuntimeAsset definitions by live preparation lease; environment data remains available. Rebuild preserves mesh/material IDs and repacks morph streams, replaces asset and streaming texture lease references and forces shared light/joint/morph uploads. Streaming callbacks rebind to new managers; old GPU resources are disposed. GPU format/pipeline state, HDR/IBL, depth/shadows, LOD groups and visibility controls are restored. CPU camera objects are preserved so demo/game controllers continue working. Default ordinary frames create no new resources or waits.

Custom meshes can provide immutable packed recovery arrays to register; custom GPU-only groups/meshes without provenance fail explicitly, allowing correction and retry. Callers must reacquire renderer/GPU objects from Application after recovery. Retained source memory is additional CPU storage proportional to live shared assets, not per entity. The packed vertex/index byte total is exposed as `meshes.recoveryBytes`. Release/disposal clears mesh archives and texture preparation references.

Validation uses actual `device.destroy()` loss notification and new devices, not a simulated resource mock. Three manual recovery cycles preserve full images exactly for textured plus morph/skin/HDR/IBL scenes, preserve handles/playback and release every old buffer/texture. Warm counts stay fixed. An intentionally unprovenanced custom texture group forces a failed rebuild; removing it and retrying succeeds. Automatic recovery resumes RAF. Recovered assets unload and final disposal returns ownership to zero, with no GPU/page errors. This tests controlled destruction; it cannot reproduce every driver crash or GPU-process reset.

Measured cold recreation in one run: approximately 52–69 ms for this small scene. Exact latest timings are in `results/device-recovery.json`; adapter requests, decoding and driver compilation affect latency. No normal-frame readback/wait is used. 197 existing tests, production build and the full GPU regression pass. A regression caught synchronous asset-detachment timing; it was fixed before completing this task.

Reproduce: `npm test`, `npm run build`, `npm run validate:recovery`, `RENDERER_PREVIEW=1 npm run validate:gpu`, `npm run benchmark:gpu`. Isolated recovery preview port 5195. Raw evidence: `results/device-recovery*.json`.
