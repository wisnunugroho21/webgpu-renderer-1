## Adaptive shadows

Startup `RendererOptions.shadows` selects a power-of-two resolution from 128–2048 and one–sixteen array layers. Defaults remain 1024×1024×16 depth32float (64 MiB). Options are preflighted before renderer GPU construction and retained across recovery. A 256×256×6 target occupies 1,572,864 bytes. Changing physical dimensions requires a new renderer/application configuration; it is never a per-frame resize.

`renderer.shadows.budget` is opt-in. `configure({ maxLayers, maxTexels, minResolution })` validates an atomic immutable budget snapshot. The fixed planner ranks lights by intensity/color and conservative range/distance influence, applying 15% retention hysteresis and deterministic rank ties. It admits all point faces/cascades together, reduces local-light distance tiers and resolution to fit the texel budget, and disables lower-priority lights without skipping projection validation. Viewports and PCF coordinates use existing array layers/pipelines; no GPU resources are created by selection. Default disablement retains strict authored overflow validation.

Texel budgets cover selected shadow-map viewport area, including cached maps, rather than guaranteeing frame time or physical memory. Whole attachment clears still cover the physical target. Startup target dimensions control actual payload; adaptive viewport sizing primarily limits raster work. `shadowBudgetRejected` and `shadowBudgetTexels` expose admission outcomes.

Five new tests plus existing shadow tests pass; the CPU suite currently passes 287 tests across 71 files. Production authored-rendering validation compares six 256-pixel point-face viewports inside the 1024 array with an independent 256×256×6 array: zero differing image bytes. All faces remain present; selecting only five available layers rejects the point light entirely. Stable maps yield six cache hits, warm resource counters remain equal, and existing complete GPU regressions pass.

CPU planning means: approximately 0.0032 ms for 32 candidates and 0.1640 ms for 1,024 candidates. Warm reduced point shadows measure approximately 0.1 ms CPU encoding / 1.2 ms submitted GPU completion on this development machine. These are hardware-specific diagnostic timings, not a guaranteed speedup. Evidence: `benchmarks/results/shadow-budget-cpu.json`, `benchmarks/results/authored-rendering-gpu.json`, and ignored `artifacts/shadow-budget-{cpu,gpu,regression}.log`.

## Automatic texture-quality streaming

`renderer.streaming.quality` is opt-in. Register one to eight complete authored texture assets per material with ascending projected-pixel thresholds, stable keys, peak GPU/recovery estimates and async loaders. Tier zero is the current resident fallback. Observation uses conservative extracted spheres, camera projection/frustum sides and fixed per-material scratch; default cadence is thirty frames with fifteen-percent threshold hysteresis. It schedules cold maintenance after synchronous frame submission, without frame-path loads, GPU creation or memory snapshots.

Transactional `replaceMaterial` keeps current textures through loading, commits only live request/material identities, preserves scalar factors and restores the original fallback. Quality pressure first evicts unleased caches, then releases lower-priority optional residency when necessary. Admissions include existing payload and reservations; upgrades need temporary headroom for old plus new assets. Source keys deduplicate whole assets, preserving compressed mip chains and authored map transforms. Failure diagnostics/backoff prevent repeated immediate loads. Registration automatically retires when a material slot's lifetime changes; material generation storage is CPU-only and does not alter the GPU ABI. Recovery suspends/drains maintenance and retains profiles/current tiers against remapped groups.

Ten targeted CPU tests pass for selection/hysteresis, visibility, pressure, failures, drain/resume, immutable inputs, lease publication/fallback/cancellation and recycled material identities. Production memory validation renders high/medium/retained-during-downgrade references, preserves exact recovered pixels/profile identity, falls back automatically under a lowered budget, reports zero controller failures, creates no warm GPU resources and disposes to zero tracked bytes. CPU observation means are about 0.0447 ms for 1,000 objects and 0.4295 ms for 10,000 objects per sweep. Evidence: `benchmarks/results/texture-quality-{cpu,gpu}.json` and ignored `artifacts/texture-quality-{cpu,gpu}.log`.

Quality remains author-defined whole-asset tiers rather than partial GPU mip residency. The controller cannot reclaim fixed pools or caller-owned fallback textures. Projected sphere diameter is conservative and does not infer arbitrary UV density; authored thresholds set desired texel density. Normal updates require immediate synchronous command submission before queued maintenance; explicit recovery/disposal drains pending loaders. Do not retain unsubmitted command buffers across resource configuration/retirement.

## Particle visibility and atlas filtering

Opt-in culling uses fixed masks and a retained frustum. Conservative spheres match analytic spawn motion, include maximum authored curve sizes and rotated corners, and enclose ribbon endpoints plus the four-times-width miter cap. Both alpha and additive order streams omit wholly hidden records. Dirty spawn rows still upload independently of visibility, preserving camera re-entry without record reuploads. Visible/culled counters are separate from simulation counts.

Optional tile-safe mipmaps share the cold material downsampler. RGB is alpha-weighted in linear space and written as straight alpha; independent per-mip frame clamps and explicit trilinear filtering prevent neighbor-frame bleeding. Chains stop before either tile dimension becomes fractional or one texel. Defaults preserve previous pixels and resource counts.

Four targeted tests pass and the full suite passes 301 tests in 74 files. Production GPU validation reports zero differing bytes with edge-intersecting billboards and a ribbon crossing both sides of the view, preserves resident rows on camera re-entry, checks minified atlas frame colors and transparent RGB halos, and creates no warm GPU objects. Existing particle deformation, blending, recovery, depth-fade and HDR checks pass. CPU means: 0.0385 ms / 0.3968 ms for 1,000 / 10,000 bounds. GPU benchmark compares 4,000 offscreen particles with culling enabled/disabled; see `benchmarks/results/particle-culling-gpu.json`. CPU evidence: `benchmarks/results/particle-visibility-cpu.json`. Development-machine timings are diagnostic, not a universal speedup guarantee.

## Motion and temporal anti-aliasing

Optional `renderer.antialiasing = "taa"` prepares shared current/previous pose storage, six bounded motion variants, and one fullscreen resolve. Fixed generational identity matching supports extraction reorder and rejects new entities/materials/meshes/deformation owners. Motion uses the same four/eight-influence skin rules and signed target-major morph-before-skin order, with previous palettes retained by GPU copies. Changed object rows coalesce; stationary scenes transfer only 304 control bytes. No per-actor GPU objects, CPU deformation, normal-frame fences or readbacks are introduced.

TAA retains RGBA32F velocity/previous-depth/validity, an opaque color snapshot, and two RGBA16F/R32F history pairs (48 bytes/pixel). It applies depth rejection, luminance/chroma neighborhood clipping, an eight-sample subpixel sequence, stable-grid accumulation and bounded stationary-edge support. Comparing opaque/composed radiance rejects transparent contributions per pixel without additional material/effect pipeline permutations. Resolve copies back into shared linear scene storage before bloom/presentation. Optional GPU-selected LOD geometry conservatively rejects history; transparent coverage remains current-frame shaded. Explicit camera cuts call `reset`; resize/recovery invalidate automatically. Controls and histories stay bounded and retained through warm mode toggles.

Three CPU tests pass for reorder/lifetime/topology resets and jitter restoration. Production GPU validation verifies analytic rigid velocity +0.0375 UV, camera velocity -0.0375, combined morph/skin velocity +0.1125, stationary velocity zero, exact unjittered first-frame/recovery references, reactive transparency and resize invalidation. A failed stability test was fixed before proceeding: successive presentation-byte variation for a static rotated cube falls from 1,585,024 (jittered without history) to 96,687 (TAA), about 94%. Warm resources stay unchanged and disposal returns tracked buffers/textures to zero. CPU identity packing/capture means are about 0.1002 ms / 1.1394 ms for 1,000 / 10,000 objects. Production evidence includes a 1,001-object none/TAA comparison; timings are hardware-specific and include diagnostic readbacks. See `benchmarks/results/{motion-history-cpu,temporal-gpu}.json`.

## Authored transmission and volume

Optional `renderer.transmission.enabled` forces shared linear scene storage without changing HDR exposure or anti-aliasing choices. Optical materials retain authored coverage while joining unified transparency. The loader imports transmission/volume factors, maps and transforms. Nonzero volume thickness ignores double-sidedness. Validation is atomic; impossible absorption values and unlit optical transmission are rejected.

A persistent mipmapped opaque capture supplies projected refracted lookups and roughness filtering. Shared retained mip pass descriptors/groups encode without GPU object creation or waits. Surface/coat reflection remains separate from transmitted diffuse energy, and authored absorption is applied along the estimated scaled ray. Custom surface families gain two bounded linear variants and retain their public function contract. Background resize replaces groups while reusing pipeline identities. Capture/mips skip frames with no conservative visible optical candidate. The approximation cannot sample hidden/offscreen geometry, other transparent layers, nested volume boundaries, optical shadows or joint-driven thickness changes.

Transmission R and thickness G maps occupy separate normalized layers of one linear array texture, preserving independent UVs/transforms/samplers and compressed source sampling. Authored nearest filtering is retained during cold packing. Both sources and packed arrays remain reference-counted, deduplicated and recoverable; memory diagnostics count actual layers/mips. The environment/material layout uses at most sixteen sampled textures. The shared material ABI grows from 112/448 to 136/544 words/bytes; twelve affine UV roles and eight optical-factor words account for the growth. For the default 2,048-material pool this adds 196,608 GPU bytes and the same CPU factor-storage bytes, plus one eight-byte optical fallback texture. These are intentional default allocation changes; existing non-optical pixels and algorithms remain unchanged. GPU authored diagnostics now derive the stride instead of hard-coding it; six/87-value legacy texture metadata patches remain supported.

Three new CPU tests verify factors/coverage, atomic rejection/legacy patches and a real serialized extension round trip; all 307 CPU tests, lint and the function-comment audit pass. Production GPU references verify thin-surface color, one-distance absorption, doubled model thickness, analytic IOR refraction against an opaque procedural screen gradient, mixed-resolution packed map channels/independent UVs/nearest samplers, affine map changes, deduplication, warm resources, TAA composition, maximum environment binding layout and exact recovered pixels. Previous transparency reactivity is now retained as a history-depth sentinel, fixing an edge-history recovery discrepancy before advancing. Disposal returns tracked buffers/textures to zero. Cold validation/packing averages about 2.1872 ms per 1,000 materials; production capture timings are recorded for this development machine. Evidence: `benchmarks/results/{volume-materials-cpu,transmission-gpu}.json`. Authoring semantics follow the Khronos transmission/volume specifications linked in the game guide; screen-space filtering and ray estimation are engine approximations.
